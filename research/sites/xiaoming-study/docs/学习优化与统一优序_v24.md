# 学习优化与统一优序 v24

2026-10-24，本地实现记录。当前入口是 `npm run data:build`；主课程、简码、字形迁移课的字段和引用由正式 JSON Schema 与交叉关系校验共同检查。

## 已实现的学习流程

- 初识显示本题取码概括；“取码说明”逐位给出字根、完整 ASB、实际采用的角色及来源。结果码位可点击或聚焦，对应字根和角色同步高亮。
- 字根 A 明确为记忆键位，S 使用方案原读音的声母，B 使用方案首笔分类。无音根显示小码同补码；不会把字词的推读或 S=B 的有音根当作无音根。
- 汉字解释单根、双根、三根和四根以上的取法；词语解释选字、选根、三字词末字单根的 AS 规则，以及超过五位时的截断。依据与判定共用 `encodingCandidates/encodingSteps`。
- 订正先解释原提交的第一个错误位置，继续输入后仍保留原错误依据；订正本身不重复评分。Tab 提示同时解释下一位来源。
- 解释窗口保留输入位置和部分输入，停止答题计时。查说明、字形对照及其他标签页查阅会进入辅助判定；刷新、撤销和切换训练保持相关曝光标记。
- 官方教程的“戋＝一戈”“丸＝九丶”“朱＝牛八”在与固定拆分完全相符时显示逐字说明。其他字提供可靠的取码推导与官方教程入口，不自动编造逐字拆分理由。
- 解释中的原始汉字、字根及编码保留源字符，繁中界面转换不会把“门”根替成“門”根。手机说明正文可以滚动，返回按钮保持可见。

## 简码与实际输入衔接

暂停菜单新增“完整取码”“简码训练”，繁中另有“繁中字形”。切换训练保留部分输入；同一训练进度有版本校验，先完成待订正题再切换。

简中提供 720 项、繁中提供 535 项简码。逐条取自固定上游的 `output-simple-codes.txt`，按本课程实际字形精确匹配，保留来源 SHA256 与版本。不会把简体简码机械转换为繁体分配。

| 类型 | 训练行为 |
| --- | --- |
| 六个固定一键简码 | 不 K、在 F、是 J、我 I、的 D、了 E，按键即完成 |
| 一码简字 | 首根 A 加空格，显示为如 H␣；仅输入字母不会判定完成 |
| 二码简字 | 首、次根 A，按满两键完成 |
| 三码简字 | 首根 AS 加末根 S，按满三码完成 |

上述机制依据[官方潇明规则](https://shurufa.app/ime/xiaoming)。当前固定分配表共 818 条，课程只载入本身字表中存在的对应字。该表内候选按键无重码，固定版本的分配有精确来源，不按全码前缀猜测。

简码课先要求对应完整字形取码及其先修，再独立练习简码。它有独立卡片 ID、日志和 FSRS，不把会按一个固定键算作会拆字。简码、字形与完整取码的速度样本分开，固定一键的速度不会拉低全码评分基线。

## 繁中字形

主课程继续使用官方默认 `d` 拆分；新增 455 项台湾兼容 `dt` 字形课，包括 351 项编码不同和 104 项拆分不同但编码相同的字。每项以原汉字和兼容拆分所需字根为前置，独立保存复习。

字形对照并列显示原字、根序和结果编码，例如“起”的走己与走巳，配合不同地区字体显示实际字形。依据[官方字形与笔顺说明](https://shurufa.app/learn/variation)，默认字形优先级与台湾兼容拆分是两种明确标注的口径。

离线 Noto Serif TC 子集保留 SIL OFL 许可证。验证了字体的实际 cmap，而非只检查字体族名称；455 个繁中训练字全部覆盖。另有 69 个仅在简中兼容查询中出现的字不在此区域字体字集中，查询明确标成“兼容拆分（原字形）”，使用原字形说明拆分，不冒充台标字形。

## 哪种优序更适合当前项目

当前采用相同的完整前置依赖图算法，两套课程共用 `scripts/curriculum_order.py`、相同成本定义、候选集合、局部优化与选优条件。分别选中了相同的 p=1.0 密度候选加 8 项窗口、4 遍动态规划。

### 目标和实现

每个需要独立练习的项目计一单位成本：声母、首笔、字根、汉字、词语均计入；同形同码字根与汉字共用一个节点与成本。单字词已合并的频序权重相加，字符、词语均保留原身份。不可练项目留存查阅，不算作能解锁的收益。

目标为：

```text
加权学习位置 = Σ[(1 / 词频序号) × 可独立输入时的累计练习单位] / Σ(1 / 词频序号)
```

候选比较包括旧交付路径、频序优先补齐前置、完整依赖图密度 p=0.75/1.0/1.25/1.5。密度候选把完成目标还缺的整个前置闭包计入成本，重新计算共享前置完成后的收益密度。较好的两项进入局部精确动态规划，保持所有前置约束；最后按同一指标选取。

以完整路径而非“先排字词、后补字根”为优化对象，更适合这份以映射、字根和独立回忆为前提的课程。它可以比较“多学一项基础能帮助多少后续内容”，也能避免同码共用练习重复计费。

### 取舍与限制

- 总体和各已测早期覆盖节点均改善；单个词可能延后。繁中“學習”从路径第 669 项移到第 1,084 项，“臺灣”从 1,018 移到 1,049。新指标计入完整前置，并允许已会字的其他词穿插。测试对“學習”的教学范围相应更新为前 1,200 项，未隐去这项变化。
- 每项一单位是明确的代理成本，尚不是用户的真实学习分钟数。不同字形的难度、记忆、复习与遗忘仍由实际学习日志和 FSRS 处理。
- 算法为全图启发式加局部精确优化，未证明全局最优。独立取码单元的均值更小，不等于真人学习速度提高同样百分比。
- 后续更有价值的改进是取得真实语料频率，以及足量无提示回忆耗时后估计个体成本；仍应保持到期复习优先与先修掌握门槛。
- 可选迁移训练按目标频序补齐必要前置，两套复用同一训练池生成函数；它们未强制插入主课程的均值指标。

## 数据、构建和进度安全

运行改为 `learning-runtime.json`，以共享汉字拆分表装配词语；完整 `learning.json` 仍保留全部溯源和查阅字段。简中运行数据约 12.86 MB，繁中约 12.44 MB，包含新增训练，约为以前整份加载的一半。

在同一新版功能与课程内容上，三轮独立本地 Edge 上下文对照：完整数据加载到可输入的中位数为 527.2 ms，共享数据为 414.1 ms；词典加载后并执行垃圾回收的 JS 堆约从 95.97 MB 降到 74.92 MB。仅为本机对照，原始记录见 artifacts/learning-v6-20261024/load-benchmark.json。

新增 `course.schema.json` 与 `runtime.schema.json`。构建必须通过 Ajv 的正式 Schema 校验、精简/完整课件逐项比对、原始来源哈希、官方 d/dt 拆分、根码、前置语义、取码结果、交付路径评分、下载哈希和字体 cmap 检查。旧生成入口也接到最终统一构建器。

简中采用当前 GitHub 复核源表的频序，修正此前五个频序对应差异；通过原字词和读音精确匹配保留身份，原身份清单文件不改写。源版本和修正记录单独保存在 `frequencySource`。

对照历史交付表核查简中 59,165 项、繁中 56,382 项字根及字词，编码与身份全部保留；54 项映射的固定规则另由回归测试核对。重新排序无需重置原卡片。新增迁移卡片使用独立稳定 ID，当前 v3 备份支持它们；带答案的备份会核对答案版本。

本轮另修复一个真实先修漏洞：当更深一层映射仍未掌握且等待到期时，不能跳过它、提前放行未掌握的字根。可以继续练其他可用内容，保留连续出题机制。

读音来源与“推读”标记继续保留。编码解释以方案字根读音为依据；自动推读仍需要人工逐项审校。本轮未把自动转写称为人工核准。

## 使用与复核

刷新本地网页。初识可看简短推导，点击“取码说明”查看过程；暂停菜单切换简码或繁中字形。在课程中查看单字详情也能打开取码过程和字形对照。

```powershell
npm run data:build
npm run data:validate
python scripts/assess_curricula.py
npm test
npm run test:teaching
```

`data:build` 会同步下载表和执行校验。构建需开发依赖；日常启动仍无需联网或安装开发依赖。完整重建源材料另依赖本机固定版本的用户词表、上游资料及既有注音工具。

当前独立审计资料位于 `artifacts/learning-v6-20261024/`：两套优化报告、候选参数比较、评估与编码不变证明、教学浏览器检查和截图。原输入、简繁切换、并发一致性、基础课、词典、下载、响应式布局另有相应回归命令。


最终验收：69 项单元测试、12 组新增教学浏览器场景及其余七项浏览器专项全部通过；正式结构与来源校验、字体 cmap、交付路径评分与 Git 空白检查通过。校验记录为 artifacts/learning-v6-20261024/validation.json。
