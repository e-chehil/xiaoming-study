# 数据结构与简繁优序核查

本报告是 v24 实现前的审计快照。本文发现的算法分歧、Schema、源频序、数据体积与教学缺口的后续处理见[已实现优化及统一算法](学习优化与统一优序_v24.md)。

2026-10-24 完成。核查对象为本地实际交付的两份 `learning.json`、各自元数据、来源表、当前课程 TSV、覆盖 TSV、下载清单，以及生成和运行代码。算法结论经过重算与逐项比对。

## 保存方式

| 数据 | 保存位置与格式 |

| 繁中课程 | `dist/data/traditional/learning.json`，JSON，约 25.3 MB |

| 原始材料 | TSV、CSV、XLSX、官方拆分 JSON 等，多种格式 |
| 学习进度 | 浏览器 IndexedDB，两套课程独立数据库；包括 cards、logs、daily、meta 四个对象仓库 |
| 进度备份 | 设置中导出 JSON；运行时不会把进度写回静态课程 JSON |

课程选择和主题使用 localStorage，当前标签页的答案曝光标记使用 sessionStorage。当前没有云端账户和跨设备自动同步。

## 结构与完整性

顶层已有 `version`、`curriculumVersion`、`lessonVersion`、`course`、`language`、`source`、`stats`、`curriculum`、`roots`、`items`。每个项目至少包含稳定 `id`、连续位置 `order`、类型、字词内容、编码、拼音、词频及来源标识、前置依赖和完整拆分 `parts`。

`id` 与课程位置分开，筛选后的繁中 ID 有空缺属于正常情况。`dependencies` 表示映射→字根→汉字→词语的前置关系；`practiceAlias` 使同形同码的汉字与字根共用练习。字根额外保留 `fullCode`、声母/首笔映射和覆盖信息；字词读音额外标注注音及来源。两套课程采用同一数据模型，繁中多出筛选和历史溯源报告，属于扩展字段。

## 优序是否一致

### 字词优化：一致，交付结果已重放验证

两套字词优序都复用 `learning_order/build_step_order.py`，权重为 `1/rank`，以每个汉字和每个词语各计一步的加权词语出现位置为目标。比较基线和 7 组密度贪心，取前三名做 8 项窗口、4 遍动态规划，再取指标最低的候选；两套实际均选中 `λ=1, p=2` 加局部优化。合并单字词后才插入映射与字根。

| 重放结果 | 简中 | 繁中 |
| --- | ---: | ---: |
| 优化前语料词条数 | 56,790 | 55,015 |
| 合并后交付字词步骤 | 58,768 | 55,985 |
| 与运行课程不一致步骤 | 0 | 0 |
| 字根/映射插入重放差异 | 0 | 0 |
| 基线加权步数 | 5902.250698 | 5091.400211 |
| 选中结果加权步数 | 5781.718507 | 4981.912537 |

简繁语料来源和保留策略不同，上表指标不能用于横向比较学习难度或语言效率。这些指标在单字词合并及基础、字根插入之前计算，尚未计算真实用时、字形复杂度、复习和遗忘成本，也不证明完整路径全局最优。

### 字根及基础课插入：不同

| 环节 | 简中 `prepare_data.py` | 繁中 `curate_traditional.py` |
| --- | --- | --- |
| 字根覆盖权重 | `Σ 1/log2(sourceId+2)` | `Σ 1/(frequency 或 163747)` |
| 统计范围 | 原交付字词表 | 筛选后的当前字词 |
| 同一汉字所需新字根的优先级 | 覆盖权重除以 `1+未学共享映射课数` | 覆盖权重降序 |
| 平局规则 | 首次需要位置、字形 | 稳定字根 ID |
| 字根内部映射课顺序 | 映射覆盖权重降序 | 依赖数组顺序 |

因此此前“简繁优序完全一致”的文档表述过宽。本轮已更正 README、算法说明及运行数据内的 `ranking`，并明确增加 `rootWeighting`。当前两套字根插入流程各自都可重放，依赖均成立；两者并没有使用同一个完整路径排序器。

若需要完整路径算法一致，后续应抽出共同插入器，统一覆盖收益、基础课成本和平局规则，并对插入后的实际完整路径重新评估。该工作会改变学习位置，应当作为课程排序变更单独管理。

### 运行时复习：一致

两套课程通过 `courses.mjs` 载入不同数据，复用同一个 `engine.mjs` 的前置解锁、自动评分、连续出题与 FSRS。默认参数一致，数据库分别保存。个人设置、学习历史、错误和到期时间不同，会产生不同实际出题队列。

## 源词表版本差异

简中历史优化报告的原始输入 SHA256 为 `97f608be7167945916804f31af050d3611186a973a3634f469df59a4f93af02d`。本轮从现有派生学习表恢复全部 56,790 个原词频与读音，重建字节的 SHA256 完全一致，证明历史输入可完整还原。

当前根目录《现代汉语常用词表.tsv》已换成 GitHub 复核版，SHA256 为 `8070d3d7e58feef1527a552e26dd07fe62ab2a33bac70858a0545fe983f2451c`，其中有以下频序对应变化：

| 16880 | 肚 | 舞姿 |
| 16881 | 舞姿 | 肚 |

属于明确的源版本差异，未发现这些词条缺失。当前网站仍由历史派生表生成。后续若要采用最新复核源表，需要统一输入版本、重新生成字词优序及溯源资料；原始文件本轮均未改写。

## 本轮已修正与仍需完善的部分

已修正繁中全部 27 项映射课的活动覆盖数量、加权覆盖及首次需要信息，避免沿用筛选前的 16 万级旧清单。两套课程位置范围说明均按当前长度刷新，ID 描述明确允许历史空缺；繁中频序、排序说明按真实流程更正。重建下载清单后，数据与下载哈希一致。修改前后，除了明确修正的元数据及基础课覆盖字段，所有学习内容、ID、位置、依赖、答案、别名、读音和示例的整体哈希完全相同。

仍需区分的完善事项：

1. 已有格式版本及结构检查，但没有正式 JSON Schema，也没有将这份全量审计设为每次数据构建的强制关卡。应把字段约束、引用约束与来源快照校验放入统一构建入口。
2. 简中 2,195 项、繁中 9,209 项为明确标注的自动推读，需要人工核对；两套各有 3 个字根缺少汉字示例。编码结构校验不能替代教学内容核准。
3. 词条已包含可还原取码过程的 `parts/division/rootCodes`，`encodingSteps` 能返回每一码的字根和 A/S/B 角色。可据此生成此前讨论的取码解释；复杂拆分理由仍须另配经核对的说明和证据，不能凭现有结构自动断言。
4. 两份运行 JSON 各约 25–27 MB，许多词语重复保存同一汉字拆分。后续可将字形拆分抽为共享索引、将字词按需加载；优化时需要保证稳定 ID、别名及备份兼容。
5. 筛选报告中的中间阶段统计与最终课件统计应继续明确区分；例如历史报告保留已移除的独立规则课信息，最终课程以顶层 `stats` 为准。
