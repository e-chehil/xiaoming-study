# 离线与资源加载

## 当前实现

应用版本 1.1.1。完整简中、繁中与 CC-CEDICT 三个 JSON 不拆分。public/resource-catalog.mjs 固化每个文件的字节数、SHA-256 与数据提交 52fdfea8754904c0054e417472cf34ba70cc7a76。课程、词典与学习算法均未改动。

读取顺序为：当前版本的有效本地缓存；缺少时顺序尝试 JSDMirror .com、本站、jsDelivr 官方、GitHub Pages、Netlify，去除重复地址。不会同时竞争下载完整文件；同一资源的并发请求合并，浏览器支持 Web Locks 时跨标签页合并。开发用 localhost 不向外部 CDN 发请求。

默认请求 6.5 秒未收到响应头或 15 秒没有正文数据时切换下一来源；单来源最多 180 秒。持续慢速下载显示进度，避免原来 90 秒上限导致稍慢链路反复无法完成。进度按解压后的实际字节与发布清单计算。

响应必须成功、是 JSON 内容类型、字节数和 SHA-256 匹配，并通过课程或词典结构检查。HTTP 200 的 HTML 错误页、截断或篡改数据均不会保存。下载失败保留原有有效版本。存储配额或权限失败时允许当前在线练习，但不会声称已具备离线课程。

## 缓存和进度隔离

Cache Storage 使用来源和应用目录作为命名空间，资源键含资源 ID 与内容哈希，不设置自动过期。每次使用先校验本地副本，不联网检查。无效副本只清理其自身键。完整资源验证成功后通过 Cache.put 写入。

FSRS 继续使用原 IndexedDB 数据库 xiaoming-study-dev-v5 及繁中后缀，卡片、日志、订正、设置与备份 v3 均不变。资源缓存维护不删除这些数据库。浏览器清理站点数据、隐私模式或存储回收仍可能使离线内容丢失，不能承诺浏览器永不回收数据。

## 页面与版本更新

模块 Service Worker 在应用目录注册，兼容根目录和 GitHub Pages 子目录。安装时校验并缓存页面、样式、程序、字体和小型界面资源；对 Netlify 插入的唯一固定托管注释，先精确移除再核对原 HTML 哈希，其他改写一律拒绝；不把三份大数据放进页面预取清单。

更新时先准备完整的新页面，并校验已安装课程是否可供新程序读取。课程下载或保存失败则拒绝新 Worker 安装，保留旧版页面与课程。等待旧标签页关闭后再接管，不在练习途中强制刷新。只清理本应用的过旧页面缓存，课程资源和学习进度保持独立。

首次访问仅下载选中的课程。切换到另一课程时才获取它。词典在进入字词释义、课程检索或查词功能时获取；不会阻塞基础课程启动。

## 配置与发布

SOURCE_POLICY 可关闭第三方源或调整已验证镜像。当前只启用 cdn.jsdmirror.com，排除有 429 和浏览器等待故障的 .cn。新增来源必须同步修改 index.html 的精确 connect-src 白名单。字体目前仍来自本站，font-src 保持 self。

固定提交的 CDN URL 对应数据快照；更新数据时必须同时更新预期哈希、字节数和提交，不得把新文件与旧 CDN 快照混用。先在各源验证完整下载，再发布。不能仅以 HTTP 200 判断可用。

新增源码文件需显式登记 release-files.json 并加入 Git；运行 npm run manifest 同步离线页面清单与发布哈希。npm run check 和 npm run build 都会检查离线清单是否过期，避免发布不能安装的离线页面。数据资源相同但程序更新时直接复用同哈希缓存。

## 验证范围

单元测试覆盖：固定版本配置、真实文件哈希与结构、本地优先、顺序多源与 CORS 错误、假 JSON、超时和正文中断、损坏修复、更新失败、配额失败、并发合并。

offline-browser.mjs 使用真实 Chromium Service Worker 与 Cache Storage，覆盖根目录及子目录的首次访问、断网新页面、独立简繁缓存、按需词典、筛选网址恢复、FSRS 持久性、损坏缓存恢复、坏数据更新拒绝及真实跨域失败回退。该自动化是本地网络模拟，不等于中国大陆实地长期测试。

2026-10-24 已用真实固定提交 URL 从当前执行网络完整下载三份数据，并核对 HTTPS、JSON、CORS、压缩和哈希。另用 Globalping 在中国大陆电信、联通、移动抽样请求这些资源。远程 API 只提供前 10KB 正文，本轮仅用作连通性观察，不能据此声称完整下载或全国稳定性。原始测量及详细结果保存在发布仓库以外的交付报告中。
